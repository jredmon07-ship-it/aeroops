# BUILD SPEC — Slice 3a: Dispatch ticket + check-out/in + flight-time derivation

**Status:** Approved-pending. Implements ADR-0007. Tickets DISPATCH-3a-1 (ticket+check-out), 3a-2 (check-in + derivation + property tests), 3a-3 (board surface). Builds on ADR-0004/0005/0006 conventions; the scheduling surface is FROZEN — 3a is purely ADDITIVE.

> ## Reconciliation (conductor, 2026-06-16) — binding amendments to the draft
> - **Status enum is `['open','closed','voided']`** and 3a ships **`voidDispatch(ticketId, reason)`** (`open→voided`, audited `dispatch.voided`) — the escape for a mistaken check-out. `closed→voided` NOT in 3a (correction table later). The one-open partial-UNIQUE `WHERE status='open'` excludes voided/closed.
> - **`dispatch:access` + `dispatch:create` both → owner/manager/dispatcher/cfi** (parity with `schedule:access`). No grant to mechanic/renter/student/accountant in 3a.
> - **`in >= out` is app-level validation** (ValidationError), NOT a DB CHECK (keeps meter-rollover open — [VERIFY-A]). DB CHECKs: meter non-negativity + the closed-shape check only.
> - Hobbs basis default; pilot member-FK; dispatch independent of reservation lifecycle (RESTRICT FKs).

**Scope guard (STOP+ask):** OUT = squawks/grounding (3b), pre-flight gate + balance (3c), invoicing/pricing (Phase 2), work-orders/MEL, computed currency, civil-twilight/optimizer, fuel, mobile. NO Stripe/balance. Derived flight time is ops data, not priced. Frozen: reservation/reservation_resource/resource schemas, scheduling result types, the conflict EXCLUDE, the scheduling write paths.

## 1. Data model + migration 0005
### 1.1 Core enum
`packages/core/src/scheduling/enums.ts`: `DISPATCH_STATUSES = ['open','closed','voided'] as const` + `DispatchStatus` + `isDispatchStatus`. pgEnum `dispatch_status` built FROM it (db/schema/enums.ts), barrelled.
### 1.2 Table `dispatch_ticket` (`packages/db/src/schema/dispatch-ticket.ts`)
`id` uuid PK; `org_id` uuid NOT NULL (FK→org CASCADE); `reservation_id` uuid NOT NULL (composite FK `(reservation_id,org_id)→reservation(id,org_id)` ON DELETE RESTRICT); `resource_id` uuid NOT NULL (the aircraft; composite FK `(resource_id,org_id)→resource(id,org_id)` RESTRICT); `pilot_user_id` uuid NOT NULL (composite FK `(pilot_user_id,org_id)→app_user(id,org_id)` RESTRICT); `status` dispatch_status NOT NULL DEFAULT 'open'; `hobbs_out`/`tach_out` numeric(10,1) NOT NULL; `hobbs_in`/`tach_in` numeric(10,1) NULL; `flight_time_hours` numeric(10,1) NULL (derived, persisted at close); `notes` text NULL; `opened_by` uuid NOT NULL (composite FK→app_user RESTRICT); `opened_at` timestamptz NOT NULL DEFAULT now(); `closed_by` uuid NULL (composite FK→app_user SET NULL); `closed_at` timestamptz NULL; `created_at`/`updated_at`. `UNIQUE (id, org_id)`.
### 1.3 CHECKs
`dispatch_meters_nonneg_check` (hobbs_out/tach_out ≥0; in cols ≥0 when non-null). `dispatch_closed_shape_check`: status='closed' ⇒ hobbs_in/tach_in/flight_time_hours/closed_by/closed_at NOT NULL; status IN ('open','voided') ⇒ those are NULL (a voided ticket was never closed). **NO DB `in>=out` CHECK** (app-level; rollover open — [VERIFY-A]).
### 1.4 Backstop — one OPEN ticket per aircraft
`CREATE UNIQUE INDEX dispatch_ticket_one_open_per_resource ON dispatch_ticket (resource_id) WHERE (status='open')`. Org-safe (resource_id ⇒ one org via composite FK). Concurrent 2nd open → `23505` → mapped to `already_open`. No btree_gist needed (equality).
### 1.5 RLS + grant: ENABLE+FORCE + 4 named fail-closed policies (standard GUC predicate) + `GRANT … TO aeroops_app`. (UPDATE policy needed for the status transition; records integrity held by the app single-write-path + audit + closed-shape CHECK, not by blocking UPDATE.)
### 1.6 Migration `0005_dispatch.sql` + `.down.sql`: human-gated banner verbatim; prereqs 0000–0004. Up: enum → table (+composite FKs/CHECKs/partial-unique) → ENABLE+FORCE RLS → 4 policies → grant. Down: reverse. Staged + human-gated, NEVER applied.
### 1.7 Schema tests (`dispatch-schema.test.ts`): RLS isolation; cross-org FK rejection (reservation/resource/pilot/opened_by); pilot-not-member rejection; one-open partial-unique (2nd open→23505; a closed/voided ticket does NOT block a new open); meter non-neg CHECK; closed-shape CHECK; FORCE RLS.

## 2. Core derivation (pure, property-tested) — `packages/core/src/dispatch/flight-time.ts`
`deriveFlightTime(meterOut:number, meterIn:number): number` — pure, no I/O/clock; returns billable hours rounded to 1 decimal (round-half-up applied ONCE to the difference). Domain: `meterIn >= meterOut >= 0`; equality ⇒ 0 (allowed). `meterIn < meterOut` ⇒ throws `RangeError` (caller/closeDispatch rejects with ValidationError first). Basis-agnostic (caller passes the Hobbs pair). Export from core barrel.
**Property tests (`dispatch/__tests__/flight-time.test.ts`, hard guardrail):** P1 non-negativity; P2 identity (x,x)=0; P3 monotonicity in `in`; P4 additivity across 0.1-grid splits (+ a rounding-bound property `|lhs-rhs|<=0.1` for arbitrary splits); P5 precision (output multiple of 0.1, within 0.05 of exact); P6 precondition guard (`in<out`→RangeError). Unit: out=0, 0.1 boundary, near-9999.9, equal-to-tenth. **[VERIFY]** billing granularity (0.1hr) + rollover — compliance.

## 3. API — `packages/api/src/dispatch/{open-dispatch,close-dispatch,void-dispatch,list-dispatch,types,internal}.ts`
New caps in `packages/core/src/capabilities.ts` (alphabetical) `dispatch:access`/`dispatch:create`, both → owner/manager/dispatcher/cfi (update capabilities.test.ts; keep `satisfies` exhaustive). Code-only, no DB seed.
### 3.2 `openDispatch(session,input)(+WithDb)` — authz `dispatch:create` FIRST. Input `{reservationId, resourceId, pilotUserId, hobbsOut, tachOut, notes?}`. Validate (Zod→ValidationError): UUIDs, meters ≥0 finite ≤1-decimal. Inside `withSessionOrgContextWithDb`: reservation visible + status='booked' (else `{ok:false,reason:'not_found'}`); resourceId is among the reservation's reservation_resource rows AND a visible active `kind='aircraft'` resource (else ValidationError); pilot is a member (composite FK + pre-check). INSERT ticket status='open' + audit `dispatch.opened`. On `23505` (partial-unique race) → `isUniqueViolation` (walk `.cause` for '23505') → re-query the open ticket → `{ok:false,reason:'already_open',openTicketId}`. Result `{ok:true,ticket:DispatchTicketView} | {ok:false,reason:'not_found'} | {ok:false,reason:'already_open',openTicketId}`.
### 3.3 `closeDispatch(session,{ticketId,hobbsIn,tachIn})(+WithDb)` — authz `dispatch:create`. Validate meters. Load ticket (RLS; not visible→not_found); `status!=='open'`→`{ok:false,reason:'not_open'}`; validate `hobbsIn>=hobbsOut` AND `tachIn>=tachOut` (else ValidationError); derive `flight_time_hours=deriveFlightTime(hobbsOut,hobbsIn)`; UPDATE `WHERE id=$ AND status='open'` set in-meters/derived/status='closed'/closed_by/closed_at (0 rows ⇒ lost race ⇒ not_open); audit `dispatch.closed` metadata `{hobbsIn,tachIn,flightTimeHours,basis:'hobbs'}`. Result `{ok:true,ticket}|{ok:false,reason:'not_found'}|{ok:false,reason:'not_open'}`.
### 3.3b `voidDispatch(session,{ticketId,reason})(+WithDb)` — authz `dispatch:create`. Load (RLS; not visible→not_found); `status!=='open'`→`{ok:false,reason:'not_open'}`; UPDATE `WHERE id=$ AND status='open'` set status='voided', updated_at; audit `dispatch.voided` metadata `{reason}`. Frees the aircraft (excluded from one-open). Result `{ok:true}|{ok:false,reason:'not_found'}|{ok:false,reason:'not_open'}`.
### 3.4 Reads — `getDispatchForReservation(session,{reservationIds})` authz `dispatch:access` → `Map<reservationId, DispatchTicketView|null>` (latest non-voided ticket per reservation), RLS-scoped, one `reservation_id = ANY(...)` query. Backs the board. (Defer a standalone `listDispatchTickets` — board needs only this.)
### 3.5 `DispatchTicketView` (`packages/api/src/dispatch/types.ts`, additive): `{id,reservationId,resourceId,pilotUserId,status,hobbsOut,tachOut,hobbsIn|null,tachIn|null,flightTimeHours|null,openedBy,openedAt,closedBy|null,closedAt|null}` (numerics parsed to number at the API boundary). Barrel-export all from `packages/api/src/index.ts`.
### 3.6 Reservation lifecycle: dispatch independent — do NOT modify cancelReservation/rescheduleReservation; FK RESTRICT blocks reservation hard-delete; a ticket can be closed against a now-cancelled reservation.

## 5. Edge cases
Double check-out same aircraft → already_open (partial-unique). Check-in in<out → ValidationError (no write, stays open). Re-close/re-void closed/voided → not_open. Reservation cancelled after open → ticket untouched, still closeable; FK RESTRICT blocks reservation hard-delete. Tenant isolation: cross-org reservation→not_found, cross-org resource/pilot→ValidationError/FK reject. Pilot-not-member→ValidationError. Resource not on reservation / non-aircraft / inactive→ValidationError. Concurrency on close→guarded UPDATE→not_open. Meter precision/rounding once at 1-decimal. Invariants: every row org_id+RLS; every open/close/void writes one audit row; meters write-once; NO money/balance; org_id from session only.
