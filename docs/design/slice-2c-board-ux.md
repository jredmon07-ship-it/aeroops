# Dispatch Board UX — Slice 2c (SCHED-2c)

**For:** frontend-engineer. Single-day dispatch board at `/o/[slug]/schedule/board`: resources as rows, time horizontal, reservations as blocks, drag-to-reschedule (15-min snap). Refines `docs/specs/slice-2c-reschedule-board.md` §3/§4 (do not contradict). Reuses `docs/design/slice-1-scheduling-ui.md` conventions/tokens/primitives.

> **Conductor decision (DnD mechanism):** use **native HTML5 drag-and-drop** (`draggable` + onDragStart/onDragOver/onDrop) — NO new npm dependency (avoids a registry-install risk in this environment). The **"Move to…" dialog is the keyboard/mobile path AND the fully-functional fallback**: the feature is complete via the dialog alone; drag is progressive enhancement. (The designer's `@dnd-kit` suggestion is deferred.)

## 1. Layout
Page in the existing shell. Header row: `<h1>`"Dispatch Board" + (if `schedule:create_reservation`) "+ New Reservation". Toolbar row: reuse `DateNav` (basePath `/o/[slug]/schedule/board`, prev/today/next + arrow keys, shares `?date=` with the list) + a List/Board view-toggle (`role="group"`, two Buttons; active filled). Inline feedback zone (refused-drop banner). Then the board grid.
**Grid:** sticky-left gutter (`w-36` desktop / `w-28` mobile, `bg-white border-r`) with group labels ("Aircraft"/"Instructors", `text-xs uppercase text-slate-500`) + per-resource cells (`h-16`: tailNumber `font-mono text-xs` for aircraft + displayName `text-sm font-medium truncate`). Scrollable time track: full day 00:00–24:00 at 200px/hr (`w-[4800px]`), `overflow-x-auto`, scroll to 06:00 on mount; sticky-top time axis (`h-8`) with hour labels ("6am"…"10pm") + 15-min ticks. Resource rows `h-16 relative border-b`, aircraft then instructors (group separator between).
**Block position (pure `board-layout.ts`):** `DAY_DURATION=24h`; `leftPct=clamp((startAt-dayStart)/DAY_DURATION*100,0,100)`, `widthPct=clamp((endAt-startAt)/DAY_DURATION*100,0,100-leftPct)`. Midnight-spanning clamps to edge with a dashed right border.

## 2. Blocks
Absolute `<div>` per (reservation × resource-row it occupies): `left/width` %, `top-1 bottom-1 rounded-md px-2`, `cursor-grab`. Content (truncated): time `HH:mm – HH:mm` (`text-xs font-medium text-white`); partner resource name(s) on line 2 for multi-resource (omit if block <~4% wide); a "⟳ Series" pill when `seriesId` set. **Color = deterministic hue from reservationId** (`hue=(parseInt(id.slice(0,8),16)%300)+30`, `hsl(hue,60%,45%)`, white text ≥4.5:1) so all blocks of one reservation share a hue and reds stay reserved for danger. Status: pending `opacity-60 ring-2 ring-white/50`; submitting `opacity-40 animate-pulse`; read-only `cursor-default`.
**Multi-resource linkage:** aircraft+instructor reservation = a block in BOTH rows sharing reservationId+hue. Hover/focus either → both get `ring-2 ring-white ring-offset-2`. Drag either → sibling shows `ring-2 ring-yellow-300 opacity-50` ("will also move"). Block `aria-label` includes "linked with [partner]".

## 3. Drag + reschedule flow
Native HTML5 DnD: block `draggable`; row renders 15-min drop cells (highlight `bg-brand/10 border-brand/40`) during drag; a snap-preview shows the proposed new time. On drop: snap to nearest 15-min → `newStartAt`; `newEndAt=newStartAt+originalDuration` (duration preserved); cross-row drop → `newResourceIds` = original set with the dragged resource swapped for the drop-target resource; same-row → omit newResourceIds. **Optimistic** move (pending styling) → board `aria-busy` → `rescheduleAction({reservationId,newStartAt,newEndAt,newResourceIds?})`:
- ok:true → replace optimistic block with the returned new reservation (new id; old gone); `aria-live` "Reservation moved to [time]".
- ok:false conflict/policy/conflict_and_policy → **snap back** + render reason via the existing `ConflictBanner` (reused from new/_components) in the feedback zone (auto-dismiss ~8s).
- not_found → snap back + "no longer exists, refreshing" → `router.refresh()`.
- ValidationError/server error → snap back + inline Alert.
Server action maps Forbidden/Unauthenticated/ValidationError; passes results through.
**"Move to…" dialog (keyboard/mobile + fallback):** every draggable block has a focusable "Move" trigger (Enter/Space) → Dialog with new-date (`<input type=date>`), new-start-time (`<input type=time step=900>`), and (multi-resource) a resource `<select>`; duration preserved (no end field); submit calls the same `rescheduleAction`; cancel "Keep as-is" autofocused. Same result handling. **On mobile (<640px) drag is disabled — tapping a block opens this dialog directly.**

## 4. States
loading (skeleton grid, `aria-busy`) · empty-no-reservations (overlay "No reservations on this date" + book link if cap) · empty-no-resources (Alert + manage link if `schedule:manage_resources`) · error (destructive Alert + Retry=router.refresh) · no-permission (server redirect to no-access via `requireCapability('schedule:access')`) · read-only viewer (`!hasCapability('schedule:create_reservation')` → blocks not draggable, `aria-disabled`, "View only" Badge, no DnD mounted) · drag-in-progress · drop-submitting · drop-success (block settles + aria-live, no toast) · drop-refused-conflict/policy/both (snap back + ConflictBanner) · not_found (refresh). Date nav reuses existing DateNav.

## 5. Accessibility
Board `role="region" aria-label="Dispatch board for [date]"`; rows `role="row"` labelled "[group] [resource]"; blocks `role="button"` (draggable) / `role="article"` (read-only) with full `aria-label` (time, resources, series, linked-with) + `aria-describedby` "Press Enter to open move dialog". Each block independently Tab-focusable (no roving tabindex; typical day = few blocks). Two persistent `sr-only` live regions: `aria-live="polite"` (success) + `aria-live="assertive"` (refused). Color-not-only (status via ring/shape + text; "Series" text label; "View only" text badge). Touch targets: blocks fill row height; "Move" trigger ≥44px. Contrast: white on `hsl(h,60%,45%)` ≥4.5:1; suppress secondary line on narrow blocks.
