# ADR-0011 — Training records core: operator-content + instructor-data-entry, write-once lesson records, NO computed FAA determination

**Status:** Accepted (Phase 3 entry, Slice T1 / TRAINING-T1; ratified by conductor 2026-06-19). **Owners:** architect, compliance-officer, backend-engineer. **Builds on:** ADR-0001 (RLS/`withOrgContext`), ADR-0003 (capability gate), ADR-0007 (dispatch records — the write-once + void-tombstone + composite-FK posture this mirrors). Additive; modifies no existing engine.

## Context
T1 opens the Training hub — the most regulation-sensitive surface in the product (the incumbents lean hard on FAA Part-61/141 semantics: ACS grading, §61.51 logging, endorsements, stage checks, the Part-141 80%-completion rate, digitally-signed records). The hard problem is NOT the data model; it is the **compliance boundary**: a flight-school training-records product is one careless column away from asserting an FAA determination it has no authority to make. T1's job is to store operator-defined CONTENT and instructor DATA ENTRY, demonstrably computing **zero** regulatory determinations, while leaving clean forward seams for the regulated-records slices that follow.

## Decision

### 1. Data-only posture — the hard compliance line
A **course** is operator-named content; a **course_lesson** (with a free-text `stage_label`) is operator content; an **enrollment** is a roster fact; a **lesson_record** is instructor data entry. The software interprets none of it and computes no FAA determination. Concretely: `grade_label` is FREE-TEXT (no enum/CHECK, never read to branch); `stage_label` is a free-text grouping (no `stage` table, no stage-check, no sequencing enforcement); `enrollment.status='completed'` is an operator toggle (no completion-rate precondition); the student/instructor are ANY visible org member (no role='student'/'cfi' enforcement, no CFI-of-record binding, no instructor-currency computation). The ONLY computed number is `progressRatioFromCounts(completed, total)` — a pure, clamped content-coverage ratio (`0/0 → 0%`, no div-by-zero), **NOT** a Part-141 80% / graduation / progress-to-certificate determination. Compliance PASS (T1) confirms; the disclaimers are load-bearing in the UI (the enrollment-detail progress section, the mark-complete confirm, the grade field, and the persisted record log all state "operator … — NOT a regulatory determination").

### 2. Records integrity — lesson records write-once; a mistake is VOIDED, not edited (mirrors ADR-0007)
A `lesson_record`'s content fields (`lesson_id`/`instructor_user_id`/`completed_at`/`grade_label`/`notes`/`recorded_by`) are **immutable once written** — NO `updateLessonRecord` path exists. The only mutation is `voidLessonRecord` (`status` recorded→voided, append-only tombstone with a required reason), exactly the squawk/dispatch correction posture; a voided record stays visible (struck-through, audit history) and is excluded from the progress numerator. `void_shape_check` enforces the tombstone shape; the durable "who voided" lives in `audit_log`, NOT the `voided_by` column (which is `ON DELETE SET NULL` — column-list syntax so `org_id` is preserved). Progress counts **DISTINCT** recorded `lesson_id`, so a repeat record never inflates it and void-then-re-record works. Every write path emits exactly ONE audit row.

### 3. Refusal conventions — invisible id → not_found
Operational refusals are RETURNED discriminated unions; auth/validation are THROWN. An invisible (cross-org / nonexistent) id yields `not_found` uniformly across `recordLesson`/`setEnrollmentStatus`/`voidLessonRecord`/`enrollMember`; `enrollment_not_active` is reserved for a VISIBLE-but-non-active enrollment; `lesson_not_in_course` for a lesson outside the enrollment's course; `has_records` blocks `removeCourseLesson` when ANY (incl. voided) record references the lesson (+ DB RESTRICT backstop); `duplicate` for the student+course unique. All conflations run in the safe direction (a cross-org id is indistinguishable from a nonexistent one — no cross-org existence disclosure).

### 4. Capabilities + the single write path
Two new capabilities: `training:access` (read) → owner/manager/dispatcher/cfi; `training:manage` (build courses/lessons, enroll, record, void) → owner/manager/cfi. **Student gets NEITHER in T1** — a student self-service "my progress" surface is the deferred Phase-6 portal. Code-only (CAPABILITIES alphabetical + ROLE_CAPABILITIES, `satisfies` exhaustiveness guard). `requireCapability` is the FIRST statement in every `*Impl`; org_id from session only; `apps/web` never imports `@aeroops/db`.

### 5. Isolation invariants
Four new tenant tables (`course` → `course_lesson` → `enrollment` → `lesson_record`, create-order load-bearing for composite-FK targets), each: `org_id` + FK→org CASCADE; ENABLE+FORCE RLS; 4 fail-closed policies; `UNIQUE(id, org_id)`; org-paired composite FKs on every edge; `aeroops_app` grant. Every read aggregate runs inside one `withSessionOrgContextWithDb` (no N+1, no cross-org peek). Migration **0012** + down staged with the human-gated banner, NEVER auto-applied; strictly additive (alters no existing table).

### 6. Deferred regulated-records seams — built in NONE of T1
Each of the following attaches FAA meaning and requires its own slice + a fresh compliance pass against the then-current FAR: digitally-signed records (instructor+student e-sign, encrypted PIN); a real `stage` table + Part-141 stage-check enforcement; the 80%-completion-rate + certificates/graduation gating; endorsements + library; qualification/eligibility gating (also depends on the deferred Slice-2a eligibility follow-up); document/medical/photo-ID/insurance/TSA-citizenship expiry; Part-141 audit-ready records + FSDO reporting; logbook/LogTen sync. **Forward boundary (carry-forward, mirrors [[dispatch-correction-table-predecessor]]):** any future consumer that attaches Part-61/141 sign-off meaning to a `lesson_record` MUST preserve signer identity immutably via `audit_log` (never the SET-NULL `voided_by`/`instructor_user_id` columns), MUST NOT reuse `enrollment.status='completed'`/`progressPercent` as a graduation/80% determination without a dedicated FAR-verified computation, and MUST re-verify Part-61 vs Part-141 recordkeeping/retention differences. **No money, no Hobbs/tach access** in T1 (does not trip the dispatch-correction-table predecessor).
